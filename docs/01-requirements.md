# 01 — 需求基线与非功能要求

## 目标与使用者
目标用户：A 股日频量化研究者。用户需要从本地数据库的当日完整数据执行筛选，查看有解释性的股票排名，比较历史回测结果。首次只做 `momentum_v1`，后续可拓展其他策略和 Python 因子。

## User Story 与验收
- US-01 数据：作为用户，我可以配置 Tushare Token 同步交易日历、沪深股票、历史和每日行情；指定历史日期后可以查询快照完整性。验收：日期级成功/失败状态、缺失详情、重跑幂等。
- US-02 因子：我可以对任意拥有 61 个完整市场交易日行情的股票计算四项原始因子。验收：对固定 fixture 和独立参考算法误差 ≤1e-10；拒绝 NaN/Inf。
- US-03 选股：我可以配置 `momentum_v1` 在指定交易日选出 Top N。验收：硬过滤有 reason、分数区间 [0,100]、合计 40/30/20/10、排序确定性。
- US-04 追溯：查询每次运行，得到策略/配置/数据快照 hash、输入样本量、拒绝原因、排名、因子值和日志。验收：相同版本/数据可重复且哈希一致。
- US-05 Python：我可以在注册表中使用受控 Python 策略计算原始因子。验收：严格 JSON Schema、隔离执行、超时退出、stderr 日志、Go/Python 同值。
- US-06 回测：我可以按指定日期区间执行简化日频回测。验收：T 日信号 T+1 交易，交易税费和不能成交处理、无未来字段、每日净值曲线与指标。
- US-07 UI：可以查看策略、任务、选股结果、回测摘要及数据异常；不需要在线代码编辑器。验收：错误/加载/空状态清晰。

## MVP 范围内
沪深 A 股（SSE/SZSE，不含北交所），历史上市和退市判断，61 市场交易日窗口，收盘后运行，Top 20，可配置过滤与排序但权重固定。MySQL 存储，Go HTTP API，CLI 补数据和一次选股，Python subprocess 预留并在 P08 实现。

## 非目标
券商连接/真实下单、分钟 Tick、自动盈利保证、ML 预测、分布式服务、K8s 多副本、第三方 Python 代码自由执行、复杂因子 DSL。

## 非功能约束
- 可追溯：所有运行记录包含策略代码版本、配置 hash、快照 hash、输入时间、错误/排除原因。
- 可靠性：全市场数据未通过完成度检查时不得发布“成功选股”。
- 安全：Token 仅环境变量/密钥配置；API 以本地或可信网络为前提；Python 插件必须受信任且资源受控。
- 可重复：本地 fixture 的结果与网络/数据库解耦。
- 运维：任务支持幂等重试，锁防重复，停机能恢复。

## 假设及待人工确认（不阻断前序模块）
- 生产 Go 版本、MySQL 部署路径、前端样式系统可在 P00 冻结；示例 Go module 为兼容离线验证使用 go 1.23。
- `historical_st_policy` 默认 strict；ST 数据不足时允许完成数据同步和因子计算，但**正式回测验收**必须阻断或明确提供可信的历史 ST 数据。
- 回测成交费用参数在 P10 冻结，禁止写死 0 手续费。
