## 实现摘要
- 将初始 schema 从单个提案文件 `db/migrations/0001_init.sql` 转成不可变版本文件 `0001.up.sql` / `0001.down.sql`；up 建立 13 张业务表并显式设置 InnoDB、utf8mb4 与 MySQL 8.4 默认排序规则，down 仅删除本版本表。
- 新增 `db/migrations` 嵌入包，二进制携带迁移文件；loader 校验 up/down 文件成对、四位版本命名、版本连续且从 1 开始。
- 首次 up 前从 migration SQL 提取创建表名并查询 `information_schema`，拒绝接管任何同名预存表；拒绝时无 applied 版本行，预存表与数据保留。dirty up 重试时跳过首次预检以允许恢复部分 DDL。
- 新增 `internal/infrastructure/mysql.Migrator`：使用 `t_schema_migrations` 记录版本、迁移名、up/down 文件 checksum、dirty 标志、执行方向及应用时间。发现未知版本、历史断档或 checksum/name 不匹配时 fail closed。
- 每次迁移固定同一个 `sql.Conn`，按当前 schema 的 SHA-256 短标识调用 MySQL `GET_LOCK`，完成后显式 `RELEASE_LOCK`。单次 `down` 只撤销最新版本，保留迁移账本。
- MySQL DDL 非原子；每个方向开始前写 dirty 状态。若中途失败，修复外部阻塞后可用相同文件/checksum 重试；迁移文件改变时 checksum 校验拒绝继续。Up 和 down SQL 都按幂等语句编写。
- `stockquant migrate up|down` 与 Make 目标只在显式调用时执行。`down` 仅允许 `APP_ENV=development|test`；启动和 health 命令不触发迁移。
- CI quality job 启动临时 MySQL 8.4 服务，`MYSQL_TEST_DSN` 触发真实数据库测试。测试为每个用例随机创建独立 schema，结束时清理。
- 更新数据库设计、README、环境设置、测试说明、root/包级索引和 P02-01 验收项；将仓储 upsert、业务事务和 EXPLAIN 验收留给 P02-02/03。
