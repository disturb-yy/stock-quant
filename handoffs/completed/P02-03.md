## 实现摘要

- sync 沿用 `t_sync_job.task_key UNIQUE`，screen 沿用既有 `t_screening_run.run_key UNIQUE`；backtest 新增由策略/版本、日期区间、config hash、snapshot hash 和模式构成的 canonical SHA-256 run key。
- 新增 `0002` up/down 迁移，以可重试 DDL 增加回测 run key、snapshot hash、错误摘要和唯一索引。历史记录按 run_id 确定性补 key、保留原记录；未知历史 snapshot hash 保持 NULL，仓储可读取这类记录。
- 增加 sync、screening、backtest 的领域状态、存储端口及 MySQL 仓储。创建操作依赖唯一约束处理并发；普通 INSERT 遇到 MySQL 1062 后按业务键读取既有记录，不依赖 `RowsAffected` 配置。哈希只接受协议要求的小写 64 位十六进制。
- 状态只能从 PENDING 进入 RUNNING，再到 SUCCESS/FAILED/BLOCKED；终态不能覆盖。sync 每次开始执行递增 attempts。
- screening 结果批次、总数、拒绝摘要和 SUCCESS 在一个事务中提交。分页按 rank 升序、未排名项最后、ts_code 升序；保留原始因子、分数和过滤理由 JSON。
- 更新数据库/API/运维文档、根索引及受影响 package 的 `AGENTS.md`/`INDEX.md`。
