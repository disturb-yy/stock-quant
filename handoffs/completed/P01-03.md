## 实现摘要
- `internal/market/ports` 定义 `SnapshotRepository` 与 `MarketDataProvider`。快照仓储读取已就绪快照；provider 负责交易日历来源，避免把上游请求与本地快照读取混成一个接口。
- `internal/factor/ports.FactorRunner` 使用已冻结的协议 v1 `contracts.FactorRequest/FactorResult`，因为它是 worker 协议边界；因子 domain 保持不依赖 infrastructure。
- `internal/screening/ports.ScreeningStore` 只保存 `screening/domain.RunMetadata`。目前不引入候选/评分类型或 P07 行为。
- `market/domain.Snapshot` 将业务 `SnapshotHash` 与文件 `Reference.SHA256` 分开，保留 `AsOf` 日期。
- `app.FactorService` 通过构造器注入 snapshot repository 和 factor runner，固定请求 61 个市场交易日快照，构建协议请求并校验响应身份；快照失败、日期/hash 不匹配、runner 故障、取消与错误响应均返回分类错误并保留 cause。
- Fake 测试覆盖完整 Snapshot → FactorRunner 请求/返回，以及 provider 日期请求、ScreeningStore 元数据保存。依赖均为内存 fake，不连接 DB、Tushare 或 Python 子进程。
- `cmd/stockquant` 保持唯一 Composition Root；真实 adapters 到位后由此选择并注入。当前不建立全局可变注册表；受信任 Python 策略注册表依 P08-04 实现。
